# 사용자 알림 운영

## 지표 의미

- `공통 알림`: 모든 사용자에게 동일하게 보이는 broadcast 수입니다. 사용자 수만큼 DB 행을 복제하지 않습니다.
- `기기 작업`: 알림 설정 시각에 활성 기기별로 예약된 FCM 작업 수입니다.
- `Provider 접수`: FCM API가 요청을 수락한 수입니다. 실제 기기 도착이나 사용자 확인을 의미하지 않습니다.
- `앱 수신`: 실행 중인 앱이 delivery payload를 관측하고 ACK한 기기 수입니다.
- `푸시 열기`: 사용자가 시스템 알림을 눌러 앱을 연 기기 수입니다.
- `인앱 읽음`: 알림센터 또는 푸시 이동에서 broadcast를 읽음 처리한 사용자 수입니다.
- `최종 실패`: 영구 토큰 오류 또는 최대 재시도 소진으로 더 이상 자동 전송하지 않는 작업입니다.

## 운영 원칙

1. Provider 접수, 앱 수신, 푸시 열기와 인앱 읽음은 분모와 의미가 다르므로 합쳐서 `전달 완료`라고 표현하지 않습니다.
2. 앱 수신 ACK는 앱 코드가 실행되지 않는 종료 상태를 완전히 측정하지 못하므로 실제 전달률로 사용하지 않습니다.
3. 푸시 본문에는 기도제목, 상담 내용 등 민감한 사용자 데이터를 넣지 않습니다.
4. 모바일 이동 대상은 서버가 지정한 enum을 앱의 allow-list에 매핑하며 임의 URL을 실행하지 않습니다.
5. 최종 실패 증가는 비활성 토큰, Firebase 프로젝트 설정, APNs 자격증명과 공급자 장애를 순서대로 확인합니다.
6. 공통 알림은 90일 후 목록에서 제외하고, 개별 읽음은 사용자별 receipt 또는 전체 읽음 watermark로 관리합니다.
