# 작은목장 관리자 화면 디자인 적용 기준

상태: **제안** (2026-11-16). 실제 화면 수정이나 사용성 검증이 완료되었다는 뜻이 아니다. 관리자 권한은 [인증·권한 정책](../domain/security-auth.ko.md)과 서버 구현을 따른다.

## 출처와 경계

`docs 2`는 SimpleHR 자료다. `dev/ux-ui-guidelines.md`의 예측 가능성·단계적 정보 노출·오류 복구, `task-docs/sales-admin/02-ui-improvement/ui-design-improvement.md`의 셸/목록/대시보드별 작업과 상태별 화면 검수, `dev/brand-guidelines.md`의 코드 기반 시각 원본 원칙을 **방법**으로 참고한다. HR 지표·영업 파이프라인·SimpleHR 색상·간격 수치·Next.js 14 전제는 작은목장의 제품 기준이 아니다.

현재 관리자 규칙은 조용하고 밀도 높은 운영 레이아웃, 표·필터·페이지네이션·로딩·빈·오류 상태, 위험 작업의 대상/결과 확인을 요구한다([`AGENTS.md`](../../AGENTS.md)). 현재 화면은 `src/app/(protected)/page.tsx`의 QT 운영 요약, `src/app/(protected)/quiet-time/page.tsx`의 필터형 목록 등으로 구성된다. 화면 스타일은 [`src/app/globals.css`](../../src/app/globals.css)와 실제 컴포넌트를 근거로 판단한다. 새 색상·컴포넌트 토큰을 이 문서에서 확정하지 않는다.

## 적용 원칙

1. **업무 단위로 읽힌다**: 페이지 제목 아래에 현재 대상·범위·기간을 밝히고, 관리자에게 필요한 첫 조치를 앞에 둔다. 대시보드의 요약은 세부 목록으로 연결하며 장식용 대형 히어로를 넣지 않는다.
2. **목록은 조건과 결과가 붙어 있다**: 검색어·필터·정렬·페이지를 바꾼 뒤 현재 조건, 결과 수, 빈 결과의 이유와 재설정 경로를 찾을 수 있어야 한다. 숫자와 날짜의 단위·시간 기준을 보인다. 작은 화면에서는 핵심 열과 조치를 보존하고 가로 스크롤 또는 상세 진입을 명시한다.
3. **같은 상태는 같은 의미로**: 상태 배지의 문구와 색, 버튼의 위치와 용도를 도메인별로 비교한다. 색만으로 대기·성공·위험을 구분하지 않는다. 공용 컴포넌트 추출은 실제 중복과 차이를 확인한 후 결정한다.
4. **위험 작업은 결과까지 확인한다**: 회원 조치·푸시 발송·리워드/쿠폰 변경·AI 설정 전환 등은 대상, 범위, 예상 결과를 제출 전에 확인하고 실행 중 중복 제출을 막는다. 성공·부분 실패·재시도 결과를 구분한다. UI 확인은 서버 권한 검증이나 감사 기록을 대신하지 않는다.
5. **오류에서 복귀한다**: 로딩, 데이터 없음, 필터 결과 없음, API 오류, 권한 부족, 부분 실패를 다른 상태로 표현한다. 재시도 또는 목록 복귀 경로를 제공하고 입력한 조건을 불필요하게 잃지 않게 한다.
6. **키보드와 좁은 화면에서도 완료한다**: 메뉴·필터·대화상자를 키보드로 열고 닫고 초점을 되돌린다. 320px·390px 등 작은 폭에서 겹침, 문서 전체 가로 스크롤, 조치 버튼 누락을 점검한다. 이 폭은 검수 예시이며 코드의 브레이크포인트 확정값이 아니다.

## 업무별 화면 계약

| 업무 | 첫 화면에서 필요한 정보 | 필수 상태·검증 |
| --- | --- | --- |
| QT 운영·신고 | 진행/대기 건수, 필터와 대상 목록, 상세 진입 | 기간·상태 조건, 긴 본문, 빈 결과, 권한/오류, 조치 후 목록 복귀 |
| 오늘의 말씀·해설 | 날짜·게시 상태·원문/출처, 수정 또는 게시 결과 | 중복 게시 방지, 생성 중, 검토/실패/재시도, 대상 날짜 재확인 |
| 알림·푸시 | 수신 범위·채널·예약/발송 상태 | 발송 전 대상 확인, 중복 전송 방지, 부분 실패와 재시도 결과 |
| 쿠폰·리워드·AI 운영 | 현재 활성 설정과 변경 대상, 영향 범위 | 권한, 변경 전후 비교, 되돌리기/복구 가능 여부, 실패 결과 |

## UI 변경 PR의 인수 기록

- 화면·관리자 업무·기본/필터/상세 경로와 권한 경계를 적는다.
- 데스크톱, 좁은 화면, 키보드에서 검색·필터·정렬·페이지 이동·위험 조치를 점검한다. 실화면 스크린샷이나 재현 단계가 없으면 시각 검증을 `미확인`으로 적는다.
- 로딩·빈·오류·부분 실패·재시도, 긴 문자열과 결과 없음 상태를 포함한다.
- 구현 Owner와 검토자가 관찰 근거, 수정 위치, 수정 후 재확인을 남긴다. UI만 확인했다면 서버 권한·실제 운영 데이터 검증은 별도로 표시한다.

우선 적용 순서는 ① 현재 주요 목록의 조건·빈/오류 상태 인벤토리 ② 위험 작업의 대상/결과 확인 ③ 좁은 화면·키보드 동선 ④ 실제로 중복된 요소의 공용화다. 화면 변경은 별도 Issue와 검증 결과로 추적한다.
