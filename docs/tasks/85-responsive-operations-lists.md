# 작업 기록: 85 관리자 운영 목록의 좁은 화면 정보 접근

> 이 기록은 2026-11-16 로컬 검증 시점의 근거다. 현재 배포 상태는 별도로 확인한다.

## 계획과 근거

- 종류: 기존 UI 개선, 저위험. API·권한·데이터 변경 없이 QT·알림 목록의 표시만 바꾼다.
- Issue: https://github.com/ByeongDoo-Han/mypasture-admin/issues/85
- 기존 문제: 390px 로컬 QT 목록에서 940px 표의 상태·수치가 가로 스크롤 뒤에 있었다. 알림 내역은 1120px 표에 9개 지표가 나열되어 좁은 화면에서 한 항목의 값을 이어 읽기 어려웠다.
- 수용 기준: 320/390px에서 제목·상태·핵심 지표·QT 상세 링크가 가로 스크롤 없이 보이고, 넓은 화면의 표와 조회 상태가 유지된다.

## 담당과 변경

- 구현 Owner·검토: 단독 작업. 작업 계약 `.agents/tasks/MP-85-responsive-operations-lists.md`에 허용 경로 기록.
- 브랜치: `fix/admin-85-responsive-operations-lists` (최신 `dev`의 `83fb365`에서 분기). PR 없음.
- QT·알림 목록은 768px 미만에서 항목별 정보와 지표 레이아웃을 사용하고, 768px 이상에서 기존 표를 사용한다. 항목을 중복 표시하지 않도록 두 레이아웃의 표시를 상호 배타적으로 했다.
- 로컬 관리자 mock에 목록·빈 결과·장애 fixture를 추가하고 브라우저 회귀를 작성했다.
- `.agents/tasks/`는 에이전트 전용 작업 계약이므로 `.gitignore`에 추가했다.
- API·DB·환경변수·서버·모바일 영향: 없음. 현재 제품 정책 문서의 기준 변경은 없다.

## 검증

| 확인 | 대상과 환경 | 결과 |
| --- | --- | --- |
| `git diff --check` | 브랜치 작업 트리 | 통과 |
| `npm run typecheck` | Node 26.5.1, npm 11.17.0 | 통과 |
| `npm run build:prod` | `.env.prod.example`의 공개 주소로 로컬 빌드 | 통과 |
| `npm run test:e2e -- tests/e2e/operations-responsive.spec.ts --project=desktop` | 로컬 mock, Chromium, 320/390/1440px | 2개 통과 |
| 같은 명령 `--project=mobile` | 로컬 mock, 모바일 브라우저 프로젝트 | 2개 통과. 이후 빈 결과 fixture만 보완했고 화면 코드는 변경하지 않았다. |

- QT 상세 링크·상태·참여·답변, 알림의 전달 지표와 문서 전체 가로 스크롤 없음, 빈 QT 결과·QT 오류, 알림 기간 오류·빈 결과·백엔드 실패 후 재조회를 확인했다.
- 첫 실행에서 새 테스트의 중복 문구 선택자 2건이 실패해 선택자를 좁혔다. 알림 빈 결과 fixture는 UTC 날짜와 한국 날짜가 달라 한 번 실패했고 한국 시간 기준으로 수정 후 데스크톱 재검사 통과했다. 이 실패를 제품 회귀로 판단하지 않는다.
- 변경 후 캡처는 상위 작업공간 `docs/ui-evidence/`에 320/390px으로 보관했다. 키보드 전용 조작과 실제 운영 데이터는 검사하지 않았다.
