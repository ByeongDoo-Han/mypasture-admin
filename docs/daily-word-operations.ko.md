# 오늘의 말씀 검수 화면

## 운영 순서

1. `게시 준비 현황`에서 오늘과 내일의 게시 상태, 활성·실패 작업을 먼저 확인합니다.
2. `운영 사건`에서 게시 누락, 생성 실패, 생성 지연을 확인하고 대응을 시작하면 `확인` 처리합니다.
3. 정상 흐름은 `초안 생성`으로 대상일의 비동기 생성 작업을 등록합니다.
4. AI 장애 시 `수동 복구 초안`에서 실제 성경 구절을 검색·선택해 묵상과 실천 질문을 저장합니다.
5. `최근 생성 작업`에서 대기, 생성 중, 완료, 실패, 취소 상태를 확인합니다.
6. 검수 목록에서 DB 성경 원문과 묵상, 실천 질문을 대조한 뒤 게시하거나 반려합니다.
7. 게시와 앱 노출을 확인한 뒤 운영 사건을 해결 처리합니다.

## 대시보드 해석

- `MISSING`: 해당 날짜 콘텐츠가 없어 생성이 필요합니다.
- `DRAFT`: 초안은 있으나 관리자 검수와 게시가 필요합니다.
- `REJECTED`: 반려 사유를 확인하고 재생성하거나 새 초안을 준비합니다.
- `PUBLISHED`: 앱과 알림에서 사용할 수 있는 게시본입니다.
- 예상 비용은 선택한 날짜 범위의 현재 콘텐츠에 저장된 생성 시점 비용 합계이며 OpenAI 청구서와 소수점 반올림 차이가 날 수 있습니다.
- 실패 작업이 누적되어도 서버는 생성 작업 행 전체를 내려주지 않고 상태별 DB 집계를 반환합니다.

`AI 모델 > 오늘의 말씀`에서 생성 모델, 추론 강도와 최대 출력 토큰을 별도로 관리합니다. 오늘의 말씀은 관리자 검수 후 게시하므로 현재 자동 평가 모델과 자동 수정 설정은 사용하지 않습니다. AI 목자의 설정과 변경 이력에는 영향을 주지 않습니다.

## 안전 장치

- 생성, 수정, 게시, 반려는 각각 `operationId`로 멱등 처리됩니다. 네트워크 결과가 불명확한 재시도에는 같은 ID를 재사용합니다.
- 게시와 반려는 최종 확인을 요구하며 관리자, 사유, 대상, 시각을 감사 로그에 저장합니다.
- 웹 클라이언트는 JWT를 읽지 못하는 HttpOnly cookie를 사용하고 same-origin 요청만 백엔드로 대리합니다.
- 이미 게시된 콘텐츠는 AI 재생성으로 덮어쓸 수 없습니다.
- 수동 초안을 저장하면 같은 날짜의 활성 AI 작업은 취소되며, 이미 외부 요청을 보낸 worker의 늦은 결과도 수동 초안을 덮어쓸 수 없습니다.
- 성경 검색 프록시는 관리자 로그인과 검색어 길이를 검증하며 백엔드 JWT를 브라우저 JavaScript에 노출하지 않습니다.

## 장애 대응

- 생성 실패 시 작업의 시도 횟수와 오류 메시지를 확인하고 원인을 조치한 뒤 재생성합니다.
- 당일 게시본이 없으면 공개 API는 404를 반환하고 FCM은 발송하지 않습니다.
- 발행 전에는 성경 버전, 권, 장, 절, 원문이 운영 DB와 일치하는지 반드시 확인합니다.
- `WARNING`은 복구 준비 단계, `CRITICAL`은 즉시 수동 복구 여부를 결정해야 하는 상태입니다. 동일 사건의 반복 감지는 새 메일을 만들지 않고 심각도 상승 또는 재발 때만 알립니다.
