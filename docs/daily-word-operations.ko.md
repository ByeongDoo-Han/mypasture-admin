# 오늘의 말씀 자동 게시·예외 복구

## 정상 운영

월 소망, 화 감사, 수 사랑, 목 평안, 금 기쁨의 선정 본문을 자동 게시합니다. 토·일에는 주제 제한 없이 정해진 문맥 범위를 순서대로 함께 읽습니다. 새 본문을 매일 AI로 생성하거나 관리자가 매일 검수할 필요가 없습니다.

`게시 준비 현황`에서 오늘·내일 게시 상태를 확인하고 `게시 상태 · 예외 초안`에서 권·장·절 범위, 전체 원문, 주제와 본문 유형을 봅니다. 자동 `CURATED` 게시본은 관리자 검수 시각·사용자가 없으면 `일일 관리자 검수 없음`으로 표시하며 검수를 가장하지 않습니다. 구버전 단일절·AI·수동 콘텐츠와 기존 감사 이력도 유지됩니다.

1. 정상 게시 여부를 확인합니다. 이미 게시된 본문에는 게시 버튼이 표시되지 않습니다.
2. 누락·원문 오류가 있으면 `운영 사건`을 확인하고 대응 시작 시 `확인` 처리합니다.
3. 자동 복구가 안 되는 날짜만 `수동 복구 초안`에서 실제 성경 구절과 안내문을 준비합니다.
4. 예외 초안을 원문과 대조한 뒤 게시하거나 반려하고 앱 노출을 확인합니다.
5. 운영 사건을 해결 처리하며 이메일 outbox의 실패 건은 원인 조치 후 필요한 작업만 재처리합니다.

`기존 AI 초안 도구`는 접힌 상태로 남겨 이전 생성 환경을 지원합니다. 자동 순환이 켜진 서버는 AI 초안 생성 요청을 명시적으로 거절하므로 반복 요청하지 않습니다. 기존 `AI 모델 > 오늘의 말씀` 설정과 AI 목자 설정은 별개이며 자동 순환에는 매일 모델 호출이 없습니다.

## 상태와 호환성

- `MISSING`: 자동 게시·원문 상태를 확인해야 합니다.
- `DRAFT`: 보호된 예외 초안으로 관리자 확인·게시가 필요합니다.
- `REJECTED`: 반려 사유를 확인하고 수동 복구 또는 수정을 준비합니다.
- `PUBLISHED`: 저장된 게시본이며 자동 순환이 바뀌어도 기존 본문을 덮어쓰지 않습니다.
- 범위 본문은 `passageText`, 첫 절 원문은 기존 `verseText`입니다. 추가 메타데이터가 없는 응답은 기존 단일절 표시로 호환됩니다.
- 예상 비용은 기존 생성 기록의 집계이며 자동 본문과 과거 AI 비용 이력을 혼동하지 않습니다.
- 운영 데이터 조회 실패는 안내와 `다시 불러오기` 링크로 복구합니다. 관리자 권한·HttpOnly 세션 검증은 기존 방식 그대로입니다.

## 안전 장치

- 생성, 수정, 게시, 반려는 각각 `operationId`로 멱등 처리됩니다. 네트워크 결과가 불명확한 재시도에는 같은 ID를 재사용합니다.
- 게시와 반려는 최종 확인을 요구하며 관리자, 사유, 대상, 시각을 감사 로그에 저장합니다.
- 웹 클라이언트는 JWT를 읽지 못하는 HttpOnly cookie를 사용하고 same-origin 요청만 백엔드로 대리합니다.
- 이미 게시된 콘텐츠는 AI 재생성으로 덮어쓸 수 없습니다.
- 수동 초안을 저장하면 같은 날짜의 활성 AI 작업은 취소되며, 이미 외부 요청을 보낸 worker의 늦은 결과도 수동 초안을 덮어쓸 수 없습니다.
- 성경 검색 프록시는 관리자 로그인과 검색어 길이를 검증하며 백엔드 JWT를 브라우저 JavaScript에 노출하지 않습니다.
- 이메일 수신 주소는 마스킹된 값만 관리자 화면에 전달하고, 외부 메일 제공자의 오류에서 토큰·비밀번호·이메일을 제거한 요약만 저장합니다.
- 이메일 조회는 최대 31일, 페이지당 100건으로 제한합니다. 화면의 상태 요약은 상태 필터와 무관하게 같은 기간 전체를 집계합니다.
- 수동 재처리는 `DEAD`, `RETRY_WAIT` 상태만 허용합니다. 기존 시도 횟수와 오류 이력을 보존하고 관리자, 사유, 대상을 감사 로그에 남깁니다.
- 재처리는 `operationId`로 멱등 처리하므로 응답을 받지 못한 동일 요청은 같은 ID로 다시 보낼 수 있습니다.

## 장애 대응

- 자동 본문을 게시하지 못하면 DB 원문 범위와 서버 운영 사건을 확인합니다. 기존 AI 작업 실패는 이력으로 조회하며 자동 순환 중 재생성 요청을 반복하지 않습니다.
- 현재·내일 게시본 조회는 서버에서 자동 복구를 시도합니다. 모든 후보 원문이 잘못되어 게시할 수 없으면 공개 API는 기존 404를 반환하며 미게시 본문을 FCM으로 보내지 않습니다.
- 발행 전에는 성경 버전, 권, 장, 절, 원문이 운영 DB와 일치하는지 반드시 확인합니다.
- `WARNING`은 복구 준비 단계, `CRITICAL`은 즉시 수동 복구 여부를 결정해야 하는 상태입니다. 동일 사건의 반복 감지는 새 메일을 만들지 않고 심각도 상승 또는 재발 때만 알립니다.
- `RETRY_WAIT`는 자동 재시도 예정, `DEAD`는 자동 재시도를 모두 소진한 상태입니다. `DEAD`는 SMTP 설정, 인증, 발송 한도, 수신 주소 정책을 먼저 조치한 뒤 필요한 작업만 수동 재처리합니다.
